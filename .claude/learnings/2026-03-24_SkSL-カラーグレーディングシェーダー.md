## 今日学んだ概念

### カラーマトリクス（4×5 行列）
- **何か**: 色変換を「4行5列の数値テーブル」で表現する仕組み。R/G/B/A の各チャンネルを線形変換する
- **なぜ必要か**: 明るさ・コントラスト・彩度・色温度など、多くの色調整は線形な計算で表現できる。マトリクスにまとめると GPU に一括転送できて高速
- **構造**:
  ```
  [rr, rg, rb, ra, r_bias]   // 出力 R = rr*R + rg*G + rb*B + ra*A + r_bias
  [gr, gg, gb, ga, g_bias]   // 出力 G
  [br, bg, bb, ba, b_bias]   // 出力 B
  [ar, ag, ab, aa, a_bias]   // 出力 A（アルファ）
  ```
- **例え**: 音楽の EQ（イコライザー）が各周波数帯を個別に増減するように、このマトリクスが R/G/B 各チャンネルを個別に混ぜ合わせる

### 行列の合成（`mulMatrix`）
- **何か**: 2つのカラーマトリクスを1つに合成する計算（行列積）
- **なぜ必要か**: 「明るさ → コントラスト → 彩度 → 色温度」と順番に4つのマトリクスを適用したいとき、1回の GPU 演算で済むよう事前に合成できる
- **例え**: 「右に3歩・前に2歩」という2つの移動指示を「右斜め前に3.6歩」という1つの指示にまとめるイメージ
- **注意点**: 行列積は順番が重要。`A×B ≠ B×A`。`mulMatrix(T, mulMatrix(S, mulMatrix(C, B)))` は「B を先に、T を最後に」適用する順序

### SkSL（Skia Shading Language）
- **何か**: Skia グラフィックスライブラリが使うシェーダー言語。GLSL（OpenGL Shading Language）に非常に似た構文
- **なぜ必要か**: カラーマトリクスでは表現できない「ピクセルの明るさに応じて処理を変える」非線形な色調整に必要
- **例え**: カラーマトリクスが「全体に同じフィルターフィルム」を貼るとしたら、シェーダーは「各ピクセルを個別に判断して色を塗り替えるプログラム」

### uniform（ユニフォーム変数）
- **何か**: CPU 側（TypeScript）からシェーダーに渡す定数。シェーダー実行中は変わらない
- **なぜ必要か**: スライダーの値など外部の調整パラメータをシェーダーに渡すための仕組み
- **例え**: レストランのシェフ（シェーダー）に「今日の塩加減はこれで」と指示する指示書

### `uniform shader image`
- **何か**: 前段で処理済みの画像をシェーダーの入力として受け取る特殊な uniform
- **なぜ必要か**: パイプライン処理（Surface 1 → Surface 2 → ...）で前の結果を次のシェーダーが読むため
- **例え**: 写真現像の工程を次の工程に引き渡すような仕組み

### `smoothstep(edge0, edge1, x)`
- **何か**: `x` が `edge0` から `edge1` に向かうにつれて 0.0 → 1.0 に滑らかに変化する関数
- **なぜ必要か**: シャドウ/ミッドトーン/ハイライトの境界を「くっきり切り替え」でなく「なめらかにブレンド」するため
- **例え**: 白黒のスイッチではなく、照明を徐々に明るくするディマー（調光器）のイメージ

### `hue2rgb()` — 色相から RGB への変換
- **何か**: 色相角（0〜360度）を RGB のベクトル（3つの数値）に変換するヘルパー関数
- **なぜ必要か**: シェーダーの中では `hsl()` のような便利な関数が使えないので、自分で実装する必要がある
- **例え**: 色相環の「角度の位置」を R/G/B の混合割合に翻訳する計算

### オフスクリーンレンダリング（`Skia.Surface.Make`）
- **何か**: 画面に表示せず、メモリ上だけで描画処理を行う「仮想キャンバス」
- **なぜ必要か**: 保存時に画像ファイルとして書き出すために、表示とは独立して描画結果を JPEG にエンコードする必要がある
- **例え**: 舞台の裏で準備した完成品を最後に写真に撮るイメージ

### `BlendMode.Overlay`
- **何か**: 2つの画像を「オーバーレイ」で重ねるブレンドモード。暗い部分はより暗く、明るい部分はより明るくなるコントラスト強調効果
- **なぜ必要か**: グレインをただ重ねると画像が明るくなりすぎる。Overlay にするとフィルムグレインらしい自然な質感になる
- **例え**: 透明なざらざらフィルムを写真に重ねたような効果

## 書いたコード

### カラーマトリクス演算（TypeScript）

```typescript
const clamp = (v: number, min: number, max: number) =>
  Math.min(max, Math.max(min, v));

// 4×5カラーマトリクスの行列積
const mulMatrix = (a: number[], b: number[]): number[] => {
  const out = new Array<number>(20).fill(0);
  for (let row = 0; row < 4; row++) {
    for (let col = 0; col < 4; col++) {
      let sum = 0;
      for (let k = 0; k < 4; k++) {
        sum += a[row * 5 + k] * b[k * 5 + col];
      }
      out[row * 5 + col] = sum;
    }
    // bias列 (col=4) の計算
    let bias = a[row * 5 + 4];
    for (let k = 0; k < 4; k++) {
      bias += a[row * 5 + k] * b[k * 5 + 4];
    }
    out[row * 5 + 4] = bias;
  }
  return out;
};
```

**ポイント解説:**
- `row * 5 + col`: 4×5 の2次元行列を1次元配列で表現するときのインデックス計算。`row * 5` で行の先頭に飛んで `col` を足す
- bias 列（index 4, 9, 14, 19）は行列積のループとは別に処理。バイアス同士の足し算が異なるルールになるため

### 各調整マトリクスビルダー

```typescript
// 露出（明るさ）: 1ユニット = 1/3 EV として RGB を乗算
const brightnessMatrix = (stops: number): number[] => {
  const s = Math.pow(2, clamp(stops, -5, 5) / 3);
  return [
    s, 0, 0, 0, 0,
    0, s, 0, 0, 0,
    0, 0, s, 0, 0,
    0, 0, 0, 1, 0,
  ];
};

// コントラスト: 0.5 グレーを基点にスケール
const contrastMatrix = (amount: number): number[] => {
  const s = Math.max(0.05, 1 + amount / 100);
  const t = 0.5 * (1 - s); // バイアスで 0.5 を基点にする
  return [
    s, 0, 0, 0, t,
    0, s, 0, 0, t,
    0, 0, s, 0, t,
    0, 0, 0, 1, 0,
  ];
};

// 彩度: sRGB 輝度重みを使って各チャンネルを混合
const saturationMatrix = (amount: number): number[] => {
  const s = Math.max(0, 1 + amount / 100);
  const lr = 0.213, lg = 0.715, lb = 0.072;
  const dr = (1 - s) * lr, dg = (1 - s) * lg, db = (1 - s) * lb;
  return [
    dr + s, dg,     db,     0, 0,
    dr,     dg + s, db,     0, 0,
    dr,     dg,     db + s, 0, 0,
    0,      0,      0,      1, 0,
  ];
};

// 色温度 & 色かぶり: RGB チャンネルをそれぞれスケール
const temperatureTintMatrix = (temperature: number, tint: number): number[] => {
  const tf = clamp(temperature, -100, 100) / 100;
  const pf = clamp(tint, -150, 150) / 150;
  const rs = Math.max(0.1, 1 + tf * 0.9 + pf * 0.25);
  const gs = Math.max(0.1, 1 - Math.abs(pf) * 0.45 + tf * 0.05);
  const bs = Math.max(0.1, 1 - tf * 0.9 - pf * 0.25);
  return [
    rs, 0,  0,  0, 0,
    0,  gs, 0,  0, 0,
    0,  0,  bs, 0, 0,
    0,  0,  0,  1, 0,
  ];
};

// 4つを合成してまとめて返す
export const buildColorMatrix = (adj: AdjustmentState): number[] => {
  const B = brightnessMatrix(adj.brightness);
  const C = contrastMatrix(adj.contrast);
  const S = saturationMatrix(adj.saturation);
  const T = temperatureTintMatrix(adj.temperature, adj.tint);
  return mulMatrix(T, mulMatrix(S, mulMatrix(C, B)));
};
```

**各マトリクスの設計ポイント:**
- **brightnessMatrix**: `stops / 3` にしている理由 — `stops = 1` のとき `2^1 = 2`（倍）は変化が大きすぎる。`2^(1/3) ≈ 1.26`（26%増）に緩和することで自然なスライダー感度になる
- **contrastMatrix**: `t = 0.5 * (1 - s)` の役割 — `s` でスケールすると黒が黒のまま・白は白のままになる。`t` を足すことで「0.5 グレーを不動点にしてスケール」になる
- **saturationMatrix**: 各セルが `(dr + s)` や `dg` になっている理由 — `s=1`（変化なし）のとき単位行列になるよう設計されている。`(1-s)` の割合で他チャンネルの輝度成分を混ぜることで彩度を下げる
- **temperatureTintMatrix**: 色温度は「R と B を反対方向にスケール」、色かぶりは「R と B を同方向に動かし G を逆に」することで実現

### グレインシェーダー（SkSL）

```glsl
uniform float grainAmount;
uniform float seed;

half4 main(float2 coord) {
  float2 uv = coord * 0.003;
  float n = fract(sin(dot(uv + seed, float2(127.1, 311.7))) * 43758.5453);
  float g = 0.5 + (n - 0.5) * grainAmount;
  return half4(g, g, g, 1.0);
}
```

**ポイント解説:**
- `coord * 0.003`: ピクセル座標を小さな値に正規化する。`dot()` の引数の数値スケールを揃えるため
- `sin(dot(...)) * 43758.5453`: ハッシュ関数の定番パターン。大きな数を掛けて `fract()`（小数部分だけ取る）することでランダムに見える 0〜1 の値を生成する
- `0.5 + (n - 0.5) * grainAmount`: ノイズを「0.5 を中心に ±grainAmount/2 の範囲」に収める。`grainAmount=0` なら全ピクセルが 0.5 グレー（グレインなし）
- `half4(g, g, g, 1.0)`: R=G=B にすることでモノクロノイズを出力。これを `BlendMode.Overlay` で元画像に重ねてグレインにする

### カラーグレーディング SkSL シェーダー

```glsl
uniform shader image;
uniform float sh_hue; uniform float sh_sat; uniform float sh_lum;
uniform float mt_hue; uniform float mt_sat; uniform float mt_lum;
uniform float hl_hue; uniform float hl_sat; uniform float hl_lum;

vec3 hue2rgb(float h) {
  h = mod(h, 360.0) / 60.0;
  return clamp(vec3(
    abs(h - 3.0) - 1.0,
    2.0 - abs(h - 2.0),
    2.0 - abs(h - 4.0)
  ), 0.0, 1.0);
}

half4 main(float2 coord) {
  half4 c = sample(image, coord);
  float lum = dot(vec3(c.r, c.g, c.b), vec3(0.299, 0.587, 0.114));
  float sw = smoothstep(0.5, 0.0, lum);
  float hw = smoothstep(0.5, 1.0, lum);
  float mw = max(0.0, 1.0 - sw - hw);

  vec3 rgb = vec3(c.r, c.g, c.b);
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(sh_hue)*0.5+0.25, sh_sat/100.0), sw * (sh_sat/100.0));
  rgb += (sh_lum / 100.0) * sw;
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(mt_hue)*0.5+0.25, mt_sat/100.0), mw * (mt_sat/100.0));
  rgb += (mt_lum / 100.0) * mw;
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(hl_hue)*0.5+0.25, hl_sat/100.0), hw * (hl_sat/100.0));
  rgb += (hl_lum / 100.0) * hw;
  return half4(clamp(rgb, 0.0, 1.0), c.a);
}
```

**ポイント解説:**
- `half4 c = sample(image, coord)`: 前段の画像から現在のピクセルの色を読み取る。`coord` はピクセルの座標
- `float lum = dot(...)`: RGB から輝度を1つの数値で算出。`0.299/0.587/0.114` は人間の目の感度に合わせた重み（緑に最も敏感）
- `float sw = smoothstep(0.5, 0.0, lum)`: 輝度が 0.5 → 0.0 に下がるほど 0 → 1 に増える = シャドウの重み
- `float hw = smoothstep(0.5, 1.0, lum)`: 輝度が 0.5 → 1.0 に上がるほど 0 → 1 に増える = ハイライトの重み
- `float mw = max(0.0, 1.0 - sw - hw)`: シャドウでもハイライトでもない残りがミッドトーンの重み
- `hue2rgb(sh_hue)*0.5+0.25`: hue2rgb の出力（0〜1）を中間輝度域にスケール調整。`*0.5+0.25` で 0.25〜0.75 に収める
- `mix(rgb, target, weight)`: `rgb` と `target` を `weight`（0〜1）の割合でブレンド
- `rgb += (sh_lum / 100.0) * sw`: 輝度オフセット。シャドウ域に輝度値を加算/減算する

### オフスクリーンレンダリングパイプライン（TypeScript）

```typescript
export const renderFilteredImageToBase64 = (
  skImage: SkImage,
  adj: AdjustmentState
): string => {
  const w = skImage.width();
  const h = skImage.height();

  // Surface 1: カラーマトリクス適用
  const colorSurface = Skia.Surface.Make(w, h);
  if (!colorSurface) throw new Error('Skia.Surface.Make が失敗しました');
  const c1 = colorSurface.getCanvas();
  const colorPaint = Skia.Paint();
  colorPaint.setColorFilter(Skia.ColorFilter.MakeMatrix(buildColorMatrix(adj)));
  c1.drawImage(skImage, 0, 0, colorPaint);
  const colorImage = colorSurface.makeImageSnapshot();

  // グレインなしの場合はそのまま JPEG エンコード
  if (adj.grain <= 0) {
    return colorImage.encodeToBase64(ImageFormat.JPEG, 92);
  }

  // Surface 2: グレインを Overlay ブレンドで重ねる
  const grainEffect = Skia.RuntimeEffect.Make(GRAIN_SHADER_SRC);
  if (!grainEffect) return colorImage.encodeToBase64(ImageFormat.JPEG, 92);
  const grainSurface = Skia.Surface.Make(w, h);
  if (!grainSurface) return colorImage.encodeToBase64(ImageFormat.JPEG, 92);
  const c2 = grainSurface.getCanvas();
  c2.drawImage(colorImage, 0, 0);         // まず元画像を描画
  const grainPaint = Skia.Paint();
  grainPaint.setShader(grainEffect.makeShader([adj.grain / 100, 0.42]));
  grainPaint.setBlendMode(BlendMode.Overlay);
  c2.drawRect({ x: 0, y: 0, width: w, height: h }, grainPaint);

  return grainSurface.makeImageSnapshot().encodeToBase64(ImageFormat.JPEG, 92);
};
```

**ポイント解説:**
- **Surface チェーン**: `colorSurface` → `grainSurface` と段階的に処理を重ねる。各 Surface は独立したオフスクリーンキャンバス
- `makeImageSnapshot()`: Surface の現在の描画内容を `SkImage` として取り出す。これを次の Surface に渡すことでパイプラインが繋がる
- `encodeToBase64(ImageFormat.JPEG, 92)`: 品質 92% の JPEG としてエンコード。`100` にするとファイルサイズが大幅に増えるが視覚的差はほぼない
- `grainEffect.makeShader([adj.grain / 100, 0.42])`: uniform に渡す配列の順番はシェーダーの **宣言順**（`grainAmount`, `seed`）と一致させる必要がある
- `c2.drawImage(colorImage, 0, 0)` してから `drawRect` する理由: グレインシェーダーは「グレインだけ」を描くため、先に元画像を敷いてからオーバーレイで重ねる

## なぜそう書くか（設計の理由）

- **シェーダーをモジュールスコープで `Skia.RuntimeEffect.Make()` する**: コンポーネントのレンダリングごとにコンパイルすると重いため、モジュール読み込み時に1度だけコンパイルする
- **`buildGradingUniforms` を TypeScript 側に置く**: シェーダーに直接オブジェクトは渡せない（number[] しか渡せない）ため、型安全な変換レイヤーを TypeScript 側で担う
- **`hue2rgb` の `*0.5+0.25`**: もし `hue2rgb` の出力（0〜1）をそのまま使うと彩度 100% で極端な原色になりすぎる。中間の輝度帯（0.25〜0.75）に圧縮することでフィルム的な柔らかい発色になる
- **`Math.max(0.05, ...)` / `Math.max(0.1, ...)`**: スライダーを最小値まで下げても完全に黒や透明にならないよう下限値を設ける。ゼロ除算や真っ黒画像になるエッジケースを防ぐ
- **グレイン `seed = 0.42` の固定**: ランダムなシードにするとフレームごとにグレインが動いて「チカチカ」してしまう。静止した一定パターンのグレインにするため固定値を使う
