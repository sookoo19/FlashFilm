## 今日学んだ概念

### SkSL（Skia Shading Language）
- **何か**: Skia グラフィックスライブラリが使うシェーダー言語。GLSL（OpenGL Shading Language）に非常に似た構文
- **なぜ必要か**: カラーマトリクスでは表現できない「ピクセルの明るさに応じて処理を変える」非線形な色調整に必要
- **例え**: カラーマトリクスが「全体に同じフィルターフィルム」を貼るとしたら、シェーダーは「各ピクセルを個別に判断して色を塗り替えるプログラム」

### uniform（ユニフォーム変数）
- **何か**: CPU 側（TypeScript）からシェーダーに渡す定数。シェーダー実行中は変わらない
- **なぜ必要か**: スライダーの値など外部の調整パラメータをシェーダーに渡すための仕組み
- **例え**: レストランのシェフ（シェーダー）に「今日の塩加減はこれで」と指示する指示書

### `uniform shader image`
- **何か**: 前段で処理済みの画像をシェーダーの入力として受け取る特殊な uniform
- **なぜ必要か**: パイプライン処理（Surface 1 → Surface 2 → ...）で前の結果を次のシェーダーが読むため
- **例え**: 写真現像の工程を次の工程に引き渡すような仕組み

### `smoothstep(edge0, edge1, x)`
- **何か**: `x` が `edge0` から `edge1` に向かうにつれて 0.0 → 1.0 に滑らかに変化する関数
- **なぜ必要か**: シャドウ/ミッドトーン/ハイライトの境界を「くっきり切り替え」でなく「なめらかにブレンド」するため
- **例え**: 白黒のスイッチではなく、照明を徐々に明るくするディマー（調光器）のイメージ

### `hue2rgb()` — 色相から RGB への変換
- **何か**: 色相角（0〜360度）を RGB のベクトル（3つの数値）に変換するヘルパー関数
- **なぜ必要か**: シェーダーの中では `hsl()` のような便利な関数が使えないので、自分で実装する必要がある
- **例え**: 色相環の「角度の位置」を R/G/B の混合割合に翻訳する計算

## 書いたコード

### カラーグレーディング SkSL シェーダー

```glsl
uniform shader image;
uniform float sh_hue; uniform float sh_sat; uniform float sh_lum;
uniform float mt_hue; uniform float mt_sat; uniform float mt_lum;
uniform float hl_hue; uniform float hl_sat; uniform float hl_lum;

vec3 hue2rgb(float h) {
  h = mod(h, 360.0) / 60.0;
  return clamp(vec3(
    abs(h - 3.0) - 1.0,
    2.0 - abs(h - 2.0),
    2.0 - abs(h - 4.0)
  ), 0.0, 1.0);
}

half4 main(float2 coord) {
  half4 c = sample(image, coord);
  float lum = dot(vec3(c.r, c.g, c.b), vec3(0.299, 0.587, 0.114));
  float sw = smoothstep(0.5, 0.0, lum);
  float hw = smoothstep(0.5, 1.0, lum);
  float mw = max(0.0, 1.0 - sw - hw);

  vec3 rgb = vec3(c.r, c.g, c.b);
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(sh_hue)*0.5+0.25, sh_sat/100.0), sw * (sh_sat/100.0));
  rgb += (sh_lum / 100.0) * sw;
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(mt_hue)*0.5+0.25, mt_sat/100.0), mw * (mt_sat/100.0));
  rgb += (mt_lum / 100.0) * mw;
  rgb = mix(rgb, mix(vec3(lum), hue2rgb(hl_hue)*0.5+0.25, hl_sat/100.0), hw * (hl_sat/100.0));
  rgb += (hl_lum / 100.0) * hw;
  return half4(clamp(rgb, 0.0, 1.0), c.a);
}
```

**ポイント解説:**
- `half4 c = sample(image, coord)`: 前段の画像から現在のピクセルの色を読み取る。`coord` はピクセルの座標
- `float lum = dot(...)`: RGB から輝度を1つの数値で算出。`0.299/0.587/0.114` は人間の目の感度に合わせた重み（緑に最も敏感）
- `float sw = smoothstep(0.5, 0.0, lum)`: 輝度が 0.5 → 0.0 に下がるほど 0 → 1 に増える = シャドウの重み
- `float hw = smoothstep(0.5, 1.0, lum)`: 輝度が 0.5 → 1.0 に上がるほど 0 → 1 に増える = ハイライトの重み
- `float mw = max(0.0, 1.0 - sw - hw)`: シャドウでもハイライトでもない残りがミッドトーンの重み
- `hue2rgb(sh_hue)*0.5+0.25`: hue2rgb の出力（0〜1）を中間輝度域にスケール調整。`*0.5+0.25` で 0.25〜0.75 に収める
- `mix(rgb, target, weight)`: `rgb` と `target` を `weight`（0〜1）の割合でブレンド
- `rgb += (sh_lum / 100.0) * sw`: 輝度オフセット。シャドウ域に輝度値を加算/減算する

### ユニフォームビルダー（TypeScript）

```typescript
import type { ColorGradingState, ColorMixerState } from '../../types/imageProcessing';
import { COLOR_CHANNELS } from '../../types/imageProcessing';

export const buildGradingUniforms = (g: ColorGradingState): number[] => [
  g.shadows.hue, g.shadows.saturation, g.shadows.luminance,
  g.midtones.hue, g.midtones.saturation, g.midtones.luminance,
  g.highlights.hue, g.highlights.saturation, g.highlights.luminance,
];
```

**ポイント解説:**
- `ColorGradingState` は `{ shadows, midtones, highlights }` の3つのオブジェクトを持つ型
- シェーダーの `uniform float sh_hue, sh_sat, sh_lum, ...` に対応する数値配列を**宣言順通り**に作る
- 順番が大事：シェーダーの uniform 宣言の順番と配列の順番が一致していないと値が混線する

## なぜそう書くか（設計の理由）

- **シェーダーをモジュールスコープで `Skia.RuntimeEffect.Make()` する**: コンポーネントのレンダリングごとにコンパイルすると重いため、モジュール読み込み時に1度だけコンパイルする
- **`buildGradingUniforms` を TypeScript 側に置く**: シェーダーに直接オブジェクトは渡せない（number[] しか渡せない）ため、型安全な変換レイヤーを TypeScript 側で担う
- **`hue2rgb` の `*0.5+0.25`**: もし `hue2rgb` の出力（0〜1）をそのまま使うと彩度 100% で極端な原色になりすぎる。中間の輝度帯（0.25〜0.75）に圧縮することでフィルム的な柔らかい発色になる
