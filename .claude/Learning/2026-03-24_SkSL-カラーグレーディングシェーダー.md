## 今日学んだ概念

### カラーマトリクス（4×5 行列）
- **何か**: 色変換を「4行5列の数値テーブル」で表現する仕組み。R/G/B/A の各チャンネルを線形変換する
- **なぜ必要か**: 明るさ・コントラスト・彩度・色温度など、多くの色調整は線形な計算で表現できる。マトリクスにまとめると GPU に一括転送できて高速
- **構造**:
  ```
  [rr, rg, rb, ra, r_bias]   // 出力 R = rr*R + rg*G + rb*B + ra*A + r_bias
  [gr, gg, gb, ga, g_bias]   // 出力 G
  [br, bg, bb, ba, b_bias]   // 出力 B
  [ar, ag, ab, aa, a_bias]   // 出力 A（アルファ）
  ```
- **例え**: 音楽の EQ（イコライザー）が各周波数帯を個別に増減するように、このマトリクスが R/G/B 各チャンネルを個別に混ぜ合わせる

### 行列の合成（`mulMatrix`）
- **何か**: 2つのカラーマトリクスを1つに合成する計算（行列積）
- **なぜ必要か**: 「明るさ → コントラスト → 彩度 → 色温度」と順番に4つのマトリクスを適用したいとき、1回の GPU 演算で済むよう事前に合成できる
- **例え**: 「右に3歩・前に2歩」を「右斜め前に3.6歩」という1つの指示にまとめるイメージ
- **注意点**: 行列積は順番が重要。`A×B ≠ B×A`。中間変数に分けて書くと適用順序が見えやすい

### SkSL（Skia Shading Language）
- **何か**: Skia グラフィックスライブラリが使うシェーダー言語。GLSL に非常に似た構文
- **なぜ必要か**: カラーマトリクスでは表現できない「ピクセルの明るさに応じて処理を変える」非線形な色調整に必要
- **例え**: カラーマトリクスが「全体に同じフィルターフィルム」を貼るとしたら、シェーダーは「各ピクセルを個別に判断して色を塗り替えるプログラム」

### uniform（ユニフォーム変数）
- **何か**: CPU 側（TypeScript）からシェーダーに渡す定数。シェーダー実行中は変わらない
- **なぜ必要か**: スライダーの値など外部の調整パラメータをシェーダーに渡すための仕組み
- **例え**: レストランのシェフ（シェーダー）に「今日の塩加減はこれで」と指示する指示書

### `uniform shader image`
- **何か**: 前段で処理済みの画像をシェーダーの入力として受け取る特殊な uniform
- **なぜ必要か**: パイプライン処理（Surface 1 → Surface 2 → ...）で前の結果を次のシェーダーが読むため
- **使い方**: シェーダー内で `image.eval(coord)` と書くと、その座標のピクセル色を取得できる
- **例え**: 写真現像の工程を次の工程に引き渡すような仕組み

### `smoothstep(edge0, edge1, x)`
- **何か**: `x` が `edge0` から `edge1` に向かうにつれて 0.0 → 1.0 に滑らかに変化する関数
- **なぜ必要か**: シャドウ/ミッドトーン/ハイライトの境界を「くっきり切り替え」でなく「なめらかにブレンド」するため
- **例え**: 白黒のスイッチではなく、照明を徐々に明るくするディマー（調光器）のイメージ

### `hue2rgb()` — 色相から RGB への変換
- **何か**: 色相角（0〜360度）を RGB のベクトルに変換するヘルパー関数
- **なぜ必要か**: シェーダーの中では CSS の `hsl()` のような便利な関数が使えないので、自分で実装する
- **例え**: 色相環の「角度の位置」を R/G/B の混合割合に翻訳する計算

### オフスクリーンレンダリング（`Skia.Surface.Make`）
- **何か**: 画面に表示せず、メモリ上だけで描画処理を行う「仮想キャンバス」
- **なぜ必要か**: 保存時に画像ファイルとして書き出すために、表示とは独立して描画結果を JPEG にエンコードする必要がある
- **例え**: 舞台の裏で準備した完成品を最後に写真に撮るイメージ

### `BlendMode.Overlay`
- **何か**: 2つの画像を「オーバーレイ」で重ねるブレンドモード。暗い部分はより暗く、明るい部分はより明るくなる
- **なぜ必要か**: グレインをただ重ねると画像が明るくなりすぎる。Overlay にするとフィルムグレインらしい自然な質感になる

### グレインシェーダーの解像度独立化
- **何か**: `coord * 0.003` のような固定スケールだと、高解像度写真ほど grain が細かく見える
- **修正**: `coord / resolution` にすることでどの解像度でも同じ視覚的な grain 密度になる
- **仕組み**: `resolution` を `uniform float2` として渡し、UV 座標を常に 0〜1 の範囲に正規化する

### power curve（べき乗カーブ）
- **何か**: `Math.pow(x, 1.5)` のように値を乗数で変換することで、感度カーブを変える
- **なぜ必要か**: リニアスケール（`x / 100` そのまま）だと低値域が効きすぎて操作しにくい
- **例え**: カメラのシャッタースピードダイヤルが等間隔でも EV 値は倍々になるように、知覚的に自然な感度にする

### `makeShaderWithChildren` — react-native-skia の正しい API
- **何か**: `uniform shader image` を持つ RuntimeEffect に、画像シェーダーを子として渡すためのメソッド
- **正しいシグネチャ**: `effect.makeShaderWithChildren(uniforms: number[], children?: SkShader[], localMatrix?)`
  - 第2引数が `SkShader[]`（`isOpaque: boolean` ではない）
- **画像シェーダーの作り方**: `image.makeShaderOptions(TileMode.Clamp, TileMode.Clamp, FilterMode.Linear, MipmapMode.None)`
  - `makeShader()` は存在しない。必ず `makeShaderOptions` か `makeShaderCubic` を使う

### カラーマトリクス演算（TypeScript）

```typescript
const clamp = (v: number, min: number, max: number) =>
  Math.min(max, Math.max(min, v));

// 4×5カラーマトリクスの行列積
const mulMatrix = (a: number[], b: number[]): number[] => {
  if (__DEV__ && (a.length !== 20 || b.length !== 20)) {
    throw new Error(`mulMatrix: 配列長が不正です (${a.length}, ${b.length})`);
  }
  const out = new Array<number>(20).fill(0);
  for (let row = 0; row < 4; row++) {
    for (let col = 0; col < 4; col++) {
      let sum = 0;
      for (let k = 0; k < 4; k++) {
        sum += a[row * 5 + k] * b[k * 5 + col];
      }
      out[row * 5 + col] = sum;
    }
    // bias列 (col=4) の計算
    let bias = a[row * 5 + 4];
    for (let k = 0; k < 4; k++) {
      bias += a[row * 5 + k] * b[k * 5 + 4];
    }
    out[row * 5 + 4] = bias;
  }
  return out;
};
```

**ポイント解説:**
- `row * 5 + col`: 4×5 の2次元行列を1次元配列で表現するときのインデックス計算
- `__DEV__` ガード: 開発時のみ動作するアサーション。要素数が20でない配列を渡したときに即座にエラーで気づける（本番には影響なし）

### 各調整マトリクスビルダー

```typescript
// 露出（明るさ）: 1ユニット = 1/3 EV として RGB を乗算
const brightnessMatrix = (stops: number): number[] => {
  const s = Math.pow(2, clamp(stops, -5, 5) / 3);
  return [
    s, 0, 0, 0, 0,
    0, s, 0, 0, 0,
    0, 0, s, 0, 0,
    0, 0, 0, 1, 0,
  ];
};

// コントラスト: 0.5 グレーを基点にスケール
// s の下限を 0.05 にすることでスライダー最小値でも完全な黒つぶれを防ぐ
const contrastMatrix = (amount: number): number[] => {
  const s = Math.max(0.05, 1 + amount / 100);
  const t = 0.5 * (1 - s); // バイアスで 0.5 を基点にする
  return [
    s, 0, 0, 0, t,
    0, s, 0, 0, t,
    0, 0, s, 0, t,
    0, 0, 0, 1, 0,
  ];
};

// 彩度: sRGB 輝度重みを使って各チャンネルを混合
const saturationMatrix = (amount: number): number[] => {
  const s = Math.max(0, 1 + amount / 100);
  const lr = 0.213;
  const lg = 0.715;
  const lb = 0.072;
  const dr = (1 - s) * lr;
  const dg = (1 - s) * lg;
  const db = (1 - s) * lb;
  return [
    dr + s, dg,     db,     0, 0,
    dr,     dg + s, db,     0, 0,
    dr,     dg,     db + s, 0, 0,
    0,      0,      0,      1, 0,
  ];
};

// 4つを合成してまとめて返す
export const buildColorMatrix = (adj: AdjustmentState): number[] => {
  const B = brightnessMatrix(adj.brightness);
  const C = contrastMatrix(adj.contrast);
  const S = saturationMatrix(adj.saturation);
  const T = temperatureTintMatrix(adj.temperature, adj.tint);
  const BC = mulMatrix(C, B);    // まず brightness → contrast
  const BCS = mulMatrix(S, BC);  // 次に → saturation
  return mulMatrix(T, BCS);      // 最後に → temperature+tint
};
```

**各マトリクスの設計ポイント:**
- **brightnessMatrix**: `stops / 3` にしている理由 — `stops = 1` のとき `2^1 = 2`（倍）は大きすぎる。`2^(1/3) ≈ 1.26`（26%増）に緩和
- **contrastMatrix**: `t = 0.5 * (1 - s)` の役割 — `s` でスケールするだけだと黒が基点になる。`t` を足すことで「0.5 グレーを基点にしてスケール」になる
- **saturationMatrix**: `s=1`（変化なし）のとき単位行列になるよう設計されている
- **buildColorMatrix の中間変数**: `mulMatrix(T, mulMatrix(S, mulMatrix(C, B)))` より `BC` / `BCS` に分けると適用順序が読みやすい

### グレインシェーダー（解像度独立版）

```glsl
uniform float grainAmount;
uniform float seed;
uniform float2 resolution;

half4 main(float2 coord) {
  float2 uv = coord / resolution;   // 0〜1 に正規化 → 解像度に依存しない
  float n = fract(sin(dot(uv + seed, float2(127.1, 311.7))) * 43758.5453);
  float g = 0.5 + (n - 0.5) * grainAmount;
  return half4(g, g, g, 1.0);
}
```

**TypeScript 側の呼び出し:**
```typescript
const grainAmount = Math.pow(adj.grain / 100, 1.5);  // power curve で感度を調整
grainPaint.setShader(
  grainEffect.makeShader([grainAmount, Math.random(), w, h])
  //                      ^             ^seed          ^resolution(x,y)
);
```

**ポイント解説:**
- `coord / resolution`: UV 座標を常に 0〜1 の範囲に収める。解像度が変わっても同じ視覚的な grain 密度になる
- `Math.pow(adj.grain / 100, 1.5)`: power curve。スライダー低値域はなだらかに、高値域に向かって自然に強くなる
- `Math.random()`: 静止画の一発書き出しなのでフレーム間のチカチカは発生しない。保存ごとに違うノイズパターンでフィルム感が出る
- `sin(dot(...)) * 43758.5453`: ハッシュ関数の定番パターン。`fract()` で小数部分だけ取ることで 0〜1 のランダムな値を生成

### カラーグレーディングシェーダー（SkSL）

```glsl
uniform shader image;
uniform float sh_h; uniform float sh_s; uniform float sh_l;
uniform float mi_h; uniform float mi_s; uniform float mi_l;
uniform float hi_h; uniform float hi_s; uniform float hi_l;

float3 hue2rgb(float h) {
  h = mod(h, 360.0) / 60.0;
  return clamp(float3(
    abs(h - 3.0) - 1.0,
    2.0 - abs(h - 2.0),
    2.0 - abs(h - 4.0)
  ), 0.0, 1.0);
}

half4 main(float2 coord) {
  half4 c = image.eval(coord);
  float lum = dot(float3(c.rgb), float3(0.299, 0.587, 0.114));
  float sw = smoothstep(0.5, 0.0, lum);   // シャドウの重み
  float hw = smoothstep(0.5, 1.0, lum);   // ハイライトの重み
  float mw = max(0.0, 1.0 - sw - hw);     // ミッドトーンの重み

  float3 rgb = float3(c.rgb);
  rgb = mix(rgb, mix(float3(lum), hue2rgb(sh_h)*0.5+0.25, sh_s/100.0), sw*(sh_s/100.0));
  rgb += (sh_l / 100.0) * sw;
  rgb = mix(rgb, mix(float3(lum), hue2rgb(mi_h)*0.5+0.25, mi_s/100.0), mw*(mi_s/100.0));
  rgb += (mi_l / 100.0) * mw;
  rgb = mix(rgb, mix(float3(lum), hue2rgb(hi_h)*0.5+0.25, hi_s/100.0), hw*(hi_s/100.0));
  rgb += (hi_l / 100.0) * hw;
  return half4(clamp(rgb, 0.0, 1.0), c.a);
}
```

**ポイント解説:**
- `image.eval(coord)`: 前段の Surface から現在ピクセルの色を読み取る。react-native-skia では `sample()` でなく `eval()` を使う
- `float lum = dot(...)`: `0.299/0.587/0.114` は人間の目の感度に合わせた輝度重み（緑に最も敏感）
- `smoothstep(0.5, 0.0, lum)`: 輝度 0.5 → 0.0 で 0 → 1 に増える = シャドウの重み
- `hue2rgb(sh_h)*0.5+0.25`: hue2rgb の出力（0〜1）を 0.25〜0.75 の中間輝度帯に圧縮。原色が強くなりすぎるのを防ぐ

### カラーミキサーシェーダー（SkSL）

```glsl
uniform shader image;
// ch_0〜ch_23: [red_h, red_s, red_l, orange_h, ...] の順
uniform float ch_0;  uniform float ch_1;  uniform float ch_2;
// ...（ch_23 まで）

float bell(float hueDiff) {
  float d = abs(mod(hueDiff + 180.0, 360.0) - 180.0);
  return max(0.0, 1.0 - d / 30.0);  // 中心から30度の範囲で影響
}

half4 main(float2 coord) {
  half4 px = image.eval(coord);
  float3 hsl = rgb2hsl(float3(px.rgb));
  float h = hsl.x;

  float dh = 0.0; float ds = 0.0; float dl = 0.0;
  float w0=bell(h-0.0);   dh+=w0*ch_0;  ds+=w0*ch_1;  dl+=w0*ch_2;   // Red
  float w1=bell(h-30.0);  dh+=w1*ch_3;  ds+=w1*ch_4;  dl+=w1*ch_5;   // Orange
  // ...（8チャンネル分）

  float3 shifted = float3(
    mod(hsl.x + dh, 360.0),
    clamp(hsl.y + ds / 100.0, 0.0, 1.0),
    clamp(hsl.z + dl / 100.0, 0.0, 1.0)
  );
  return half4(hsl2rgb(shifted), px.a);
}
```

**ポイント解説:**
- `bell(hueDiff)`: コサインベル関数。中心色相から30度以内のピクセルだけに効果が乗る。隣の色と干渉しない
- **8チャンネルの手動展開**: SkSL はループ内の配列添字（`ch[i]`）が使えない。そのため `ch_0`〜`ch_23` として個別宣言し手動で展開している
- `rgb2hsl` → `hsl2rgb`: 色相ベースの操作をするため、一度 HSL 空間に変換して H/S/L をシフトし RGB に戻す

### renderFilteredImageToBase64（Surface chain 完全版）

```typescript
export const renderFilteredImageToBase64 = (
  skImage: SkImage,
  adj: AdjustmentState,
  colorGrading?: ColorGradingState,  // 省略可能
  colorMixer?: ColorMixerState,      // 省略可能
): string => {
  const w = skImage.width();
  const h = skImage.height();

  // Surface 1: カラーマトリクス
  const colorSurface = Skia.Surface.Make(w, h);
  if (!colorSurface) throw new Error('Skia.Surface.Make が失敗しました');
  const colorCanvas = colorSurface.getCanvas();
  const colorPaint = Skia.Paint();
  colorPaint.setColorFilter(Skia.ColorFilter.MakeMatrix(buildColorMatrix(adj)));
  colorCanvas.drawImage(skImage, 0, 0, colorPaint);
  let currentImage = colorSurface.makeImageSnapshot();
  colorSurface.dispose();  // ← スナップショット取得後に解放

  // Surface 2: カラーグレーディング（引数省略時はスキップ）
  if (colorGrading) {
    const gradEffect = Skia.RuntimeEffect.Make(COLOR_GRADING_SHADER_SRC);
    if (gradEffect) {
      const gradSurface = Skia.Surface.Make(w, h);
      if (gradSurface) {
        const imgShader = currentImage.makeShaderOptions(
          TileMode.Clamp, TileMode.Clamp, FilterMode.Linear, MipmapMode.None,
        );
        const gradPaint = Skia.Paint();
        gradPaint.setShader(
          gradEffect.makeShaderWithChildren([/* 9つのuniform値 */], [imgShader]),
        );
        const gradCanvas = gradSurface.getCanvas();
        gradCanvas.drawRect({ x: 0, y: 0, width: w, height: h }, gradPaint);
        currentImage = gradSurface.makeImageSnapshot();
        gradSurface.dispose();
      }
    }
  }

  // Surface 3: カラーミキサー / Surface 4: グレイン（同様のパターン）
  // ...
};
```

**ポイント解説:**
- `let currentImage`: 各 Surface の結果を次に引き渡す変数。`const` でなく `let` にして毎回上書きする
- `colorSurface.dispose()`: `makeImageSnapshot()` の後すぐ呼ぶ。スナップショットはピクセルデータを独自に持つので Surface を解放しても画像は保持される
- `colorGrading?`: `?` は TypeScript の省略可能引数。`undefined` のときは `if (colorGrading)` が `false` になりスキップされる
- `makeShaderOptions` (正しい) vs `makeShader` (存在しない): react-native-skia の `SkImage` には `makeShader()` がない。必ず `makeShaderOptions(tx, ty, FilterMode, MipmapMode)` を使う

## なぜそう書くか（設計の理由）

- **Surface を `dispose()` する**: `makeImageSnapshot()` を呼ぶと、以降その Surface のバッファは不要になる。解放しないと保存のたびに数十〜数百MBのネイティブメモリが積み上がりクラッシュする
- **grain seed を `Math.random()`**: この関数は UI 表示ではなく「保存」専用。毎回呼ばれるのが1回だけなのでチカチカしない。保存ごとに違うノイズ = フィルム写真の自然な揺らぎ
- **`Math.pow(adj.grain / 100, 1.5)`**: リニアより操作しやすい。スライダーを半分に動かしたとき、見た目の変化が「ちょうど半分」ではなく「少し抑えめ」になる感覚に合わせる
- **`coord / resolution` の解像度正規化**: 端末や写真の解像度に関わらず同じ grain 密度で書き出したい。`coord * 定数` は解像度依存なので NG
- **カラーミキサーの uniform を手動展開**: SkSL では `uniforms[i]` のようなランタイムインデックスが使えない。`ch_0`〜`ch_23` として宣言順に渡すしかない
- **`makeShaderWithChildren` の children が第2引数**: 設計メモには `isOpaque` が第2引数と書いてあったが、インストール済みバージョンの型定義では `(uniforms, children?, localMatrix?)` が正しい。型定義ファイルを必ず確認する
